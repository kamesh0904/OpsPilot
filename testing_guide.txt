🧭 OpsPilot — Local Testing & Verification Guide
========================================================================

Since you do not have active production data in your Slack, Notion, Linear, or GitHub accounts, this guide outlines the three best ways to test and verify that the OpsPilot project is working perfectly on your machine.

---

Method 1: Run the Automated Test Suite (Offline & Mocked)
────────────────────────────────────────────────────────────────────────
OpsPilot comes with a comprehensive, professional test suite. All external API calls, Slack delivery, and LLM responses are automatically mocked using `unittest.mock`, meaning you don't need any network access or active keys to run them.

To run all tests:
1. Ensure your virtual environment is active (or use the absolute path).
2. Execute the following command from the project root:

   .venv\Scripts\python -m pytest -v

What this verifies:
- All 4 agents (Collector, Analyst, Decision, Action) parse and function correctly.
- The LangGraph pipeline logic executes successfully.
- All FastAPI endpoints, routing, and inputs validate correctly.
- Signature security checks and custom properties parse correctly.

---

Method 2: Use the Interactive API Playground (Swagger docs)
────────────────────────────────────────────────────────────────────────
FastAPI automatically generates an interactive documentation page that allows you to trigger and explore the APIs live.

1. Start your local server:
   
   .venv\Scripts\uvicorn main:app --reload

2. Open your web browser and navigate to:
   
   http://127.0.0.1:8000/docs

3. Test the Health Endpoint:
   - Expand "GET /health".
   - Click "Try it out", then click "Execute".
   - It should return: {"status": "ok", "service": "opspilot"}

4. Test the Query Pipeline:
   - Expand "POST /api/v1/query".
   - Click "Try it out".
   - Modify the request body to ask a question, e.g.:
     {
       "question": "What is the status of the current open issues?"
     }
   - Click "Execute". The pipeline will run synchronously using your valid API keys, fetch current workspace states (even if empty), pass them to Gemini, and return the structured response in the browser!

---

Method 3: Create Minimal Sandbox Data for End-to-End Slack Flow
────────────────────────────────────────────────────────────────────────
If you want to see the magical "Action Agent" post a real daily briefing directly to your Slack channel, you can set up quick sandbox data in under 5 minutes:

1. Slack Setup:
   - In your Slack workspace, create a channel named `#ops-pilot` (or whatever SLACK_CHANNEL_ID is set to).
   - Invite your bot to the channel by typing: /invite @opspilot

2. Create One Mock Item per Service:
   - GitHub: Create a temporary public/private repository under your GitHub account (`kamesh0904`) and create a single dummy open Pull Request (e.g. "Draft: Readme Update").
   - Linear: Create a single dummy ticket on your team board (e.g., status "In Progress").
   - Notion: Create a single new page in Notion (e.g., "Team Goals Q2") and ensure your integration ("Opspilot") is shared/connected to that page.

3. Trigger the Briefing manually:
   - Ensure the server is running:
     .venv\Scripts\uvicorn main:app --reload
   - Go to http://127.0.0.1:8000/docs and expand "POST /api/v1/briefing/trigger".
   - Click "Try it out" and execute it with the default body:
     {
       "run_type": "morning"
     }
   - Observe the terminal log running the LangGraph pipeline, and watch your Slack channel receive a beautiful Daily Briefing card styled with Slack Block Kit!
